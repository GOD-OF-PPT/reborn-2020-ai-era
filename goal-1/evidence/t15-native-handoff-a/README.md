## A. 浏览器菜单200%

1. 在支持实际页面缩放的桌面浏览器打开生产5237，记录浏览器名称/版本、操作系统、窗口/页面尺寸与100%菜单状态。创建专用验证人生：点“开始一段新人生”→选背景与愿望→“下一步：看看本季的选择”→选“自由安排”（不接受经营引导）→可在“固定种子（可选）”填t15-native-zoom-日期→“开始新人生”。这是一次真实正常创建，保留runId和初始保存号，不碰旧人生。
2. 在真实住处先点“账本”→“导出已保存存档”→“下载这份存档”，保存为zoom-before.json。保持原始字节，只重命名，不格式化/重新编码。关闭产品存档对话框。
3. 用**浏览器菜单**把页面缩放改为200%，留菜单显示200%且能看到测试页的原始截图。只把视口缩小或看到DPR2不是这项证据。
4. 用原生滚动检查：四主导航“住处/机遇/手记/账本”、日期/可花/行动/保存状态、住处四热点和“桌上待办”；文字/数字/费用/期限不重叠、可阅读。允许纵向滚动；无法触达、焦点被遮或文本被裁需逐项记录为缺陷，不通过缩小字体或隐藏义务规避。
5. 在新局点“床边 · 生活”→“眼前生活”。用Tab/Shift+Tab聚焦“确认改善桌椅与照明”，Enter打开**应用命令确认**，核对个人3000元/1点/7日；只打开并按Escape取消，检查焦点回原按钮。**不要点“确认并保存安排”**，否则这轮只读前后字节检查会产生真实新操作，需另记，不能冒充未变。
6. 人物和年度：住处“人物”或生活“人物与约定”，住处“年度”或生活“年度回顾”；确认列表、人物记录、年度下拉和账本可用，键盘能到达动作。新局尚未知人物的轮廓是合法状态，不应凭空显示肖像。
7. 若需检查四名已知人物，在这份专用浏览器回入口→“导入存档”→“选择本机存档文件”选原77输入→“检查存档”→核对runId=t15-normal-people-technical_employee、提交77→“确认导入为独立人生”。若同runId已存在则停，不点恢复覆盖。导入后日期应为2022-10-21，四人物/年度可查看；这是正常前史输入的当前原生布局补验，不是原生2020—2022完整游玩。此档AP0，不能用它验证上述需要可用行动的命令确认。
8. 恢复浏览器菜单100%，留恢复截图。对第1步新局重新从入口继续正确runId，再导出zoom-after.json；对77输入可另导出people77-after.json。对比同一人生前后原始文件SHA/字节，不能拿新局和77互比。正常只读与取消不应改变原提交；77可对照[input manifest](input-manifest.json)的原SHA。保存所有实际截图/结果；菜单200%缺失或失败项未修复则本项仍未通过。

## B. 未保存候选的浏览器原生离页

1. 在**开发5238链接**打开一个新文档，确认页面出现“隔离存储验证库”和“写入成功后中止：待触发”。不要复用已经触发过的旧页面实例；不删除已有测试档。创建专用新人生，种子可用t15-native-leave-日期，记录实际runId与保存号。
2. 点“床边 · 生活”→“眼前生活”→“确认改善桌椅与照明”。应用确认页必须列个人3000元/1点/7日。这里为制造本机失败候选，**实际点“确认并保存安排”一次**。等待真实head.put后abort：页面应出现“未保存：界面仍是上一次完整提交”，故障横幅改为已触发。旧余额/行动/普通房间保留，不因候选提前换景。若无这些状态则记录失败并停，不在生产用普通成功操作冒充故障。
3. 用警示区的“导出旧已保存存档”和“导出未保存候选”，分别下载为leave-old-before.json、leave-candidate-before.json；每次关产品对话框。记录实际runId/revision/SHA。未保存候选不是物理已保存版本；这里不要点重试、舍弃或恢复。
4. 用浏览器**原生刷新/导航/关标签**触发离页，记录具体触发方式。截取浏览器原生提示（实际文案/按钮按该浏览器记录），先选“取消/留在页面”的实际对应按钮。游戏“保存退出到入口”的应用对话框不算原生提示。若未出现原生提示，记录真实行为为未通过，不能据导航中止或候选还在推断成功。
5. 留在后重新导出候选为leave-candidate-after-stay.json、旧档为leave-old-after-stay.json。原始候选前后必须逐字相同，旧档也必须逐字相同；不要在比较前重试保存或改备注。
6. 再用同一种原生方式触发离页，留第二次原生提示证据，实际选“离开/重新加载”的对应按钮。用重新加载后的新文档或另一个同源新标签，继续**同一runId**，导出leave-old-after-leave.json。新物理连接必须只读到旧完整提交，并与leave-old-before.json逐字相同；不能把应用内“重新读取”当作原生离开，也不能把候选当作已保存导出。
7. 记录浏览器/版本、实际原生按钮、时间、留在/离开两次结果、全部原始文件和SHA。未出现提示、旧档被改、候选消失/变化或某步无法观察均记失败/未决；不要填通过。候选已单独备份，若后续要恢复，应另走产品显式审阅流程并单独记录，不能混入本次原旧档比较。
