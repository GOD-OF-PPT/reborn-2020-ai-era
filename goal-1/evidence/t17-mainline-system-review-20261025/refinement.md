## 2. 统一玩家经历：每次尝试有一个可以停下的终点

玩家主线是“怎样把钱和时间换成想要的生活”，五路线是手段。每幕只需清楚回答：**我在意哪件事、现在到哪、能亲手做什么、要付出什么、下一次何时回应**。结束时再回答“这次改变了什么，愿意怎样继续”。工作、生活和副业可并行，不把焦点显示预算变成经营数量限制。

一份当前尝试在呈现层携带：完整身份、当前问题、本次公开结束条件、当前阶段、真实动作/等待、已发生结果引用、未完责任、合法去向。它是对现有公开事实的组织，不是新任务积分、新奖励、存档schema或新强制目标。阶段性终点与业务整体关闭独立：

| 尝试 | 可以停留并得到反馈的终点 | 仍要保留的事实 |
| --- | --- | --- |
| 首单/视频作品 | 交付结果，或明确拒绝/退出后的结果。 | 客户复核、修改、预款/退款、尚未收到的款不能冒充完成到账。 |
| 模拟投资 | 亲手作出判断，看到原撮合/撤单/明确不买的结果。 | 持仓可继续，部分成交与交收独立，不强求卖出或盈利。 |
| 工作/生活 | 一笔实际工资或本季在岗回响；同一生活安排/个人约定实际反馈。 | 在岗不因收到工资而结束；未来工资不是当前可花；关系不因展示肖像增加。 |
| 课程 | 教案/样课ready结束准备；班期结清结束这一次学生承诺。 | 准备不是招生，学费保护不是收入；支持、退款和旧责任仍分别存在。 |
| 中转 | 本期服务结果，及原支持、核账与到期收付各自的实际反馈。 | 服务停止不等于债务结清，客户预款与供应资产不等于利润。 |
| 生态/架空权益 | 原合作交付或一次明确有条件的权益决定得到实际反馈。 | 资格、合同、股份、锁定和现金独立，保持架空标识。 |

首段继续采用约十分钟的设计目标，未作计时结论：回应所选开局→一次有代价的决定或明确暂缓→已承诺/未承诺清楚→等谁与何时清楚→反馈后有去向。投资/自由开局不强制首单。

单季采用“这季尝试→实际所得与所失→还答应什么”；跨季将“旧约继续、旧事回看、今天新决定”分开。愿望与六年度问题只在实际选择/后果处回访，不靠更换口号制造进度。非创业、未盈利和安静季度都有可成立的叙事。

趣味性的实施单位是一项能理解的取舍：模拟投资比较研究、资金暴露与生活储备；视频比较已有合法制作方式、投入与客户修改；课程比较班额承诺与真实支持容量；中转比较已有可用供应、预算、客户条款与服务边界。选择面先给可比较的确定代价和公开约束，再展开原字段，不预报胜率或隐含最优答案。人物已实际来信或提出请求时，先让玩家看见“谁在等我、要回应什么”；没有已知身份或来往就不补对白。季末回看选择的真实得失，再允许换方向；不靠清单勾完、免费奖励或额外小游戏替代这些取舍。是否值得重试仍需真人反馈。

## 3. UI、美术与TA共用一份状态

常态画面按**处境与决定→对象→必要投入与反馈日→次要记录**组织。日期、可花资金、共享四点、保存状态只保持一组；强制责任、现金缺口和未保存状态独立可见。完整钱款/名单/权限/原文经同屏分页到达，不以缩字、裁切、滚动或省略字段获得简洁。

当前闭班主幕的目标稿：人生方向仅保“保持生活自主”；阶段文案依据实际原120改为本班已结束，并可准确说明留存4/5与实退199；保留预款995、保护0、教学收入796的具体边界。主去向按当前状态显示“看看今天可安排什么”或“另备一堂课”等准确导航名；任何新教案、生活安排或付款仍独立确认。AP0不能把新工作画成可立即执行，“看看”也不能偷执行。原120本轮未修改。

| 层次 | 统一设计与实际职责 |
| --- | --- |
| 场景 | 保冷青城市、暖灯、木材与纸白。固定镜头的房间提供日子与处境；状态变化优先发生在同一物件，不每次重绘整屏。普通/改善住处仍读实际生活状态。 |

| 已保存回响 | 原子保存后按因果显现结果与留痕。安排不庆祝交付、更正不庆祝收款；重进显示事实，不重复执行/收益。提交/存储失败保持旧场景，原候选重试成功才发布。 |

TA实现分三种来源：业务阶段读committed view；焦点/选择/翻页读本地UI；保存中/失败/只读读Session。动效不执行命令、不消费随机；图片不能包含金额、状态文字或按钮。沿原生SVG/DOM/CSS补形状、接触与状态；只有已确定接线且现资产缺失时再用imagegen补透明人物/前景。先列“公开状态→图层→动作→失败回退”，再制图。音效在闭合动作后加入默认静音的轻纸响/环境/真实结果，不能用声音掩盖不清楚的操作。纯文本、减少动效、静音保同信息。

“保旧状态”只针对提交/存储失败、冲突和未保存候选。客户拒绝、业务亏损、未达承诺等**已经保存的经营结果必须显示真实失败留痕**；不能冻结在旧成功画面，也不播成功收益。正常显选、草稿和待确认纸件仍响应UI。

## 4. 等待不能变成日常点表

原强制屏障继续按原规则停下；开工、完工、来信和需回应的新变化应解释对象与行动；没有新取舍的逐日用量与例行记账应作为真实累计报告，保完整原逐笔账。不能为少点一次而跳过费用、期限、风险或交付。

当前公开 nextDate 缺少意义分类，因此**这是待设计的接口缺口**。U4-A先核目前公开对象日程与原屏障能覆盖哪些停点，必要时提出最小公开日历合同；若必须触及原P3拥有的application/core，另行界定来源/权限/重放影响，不在UI私读队列。不得把C2修复机械推广成中转28次逐日点击，也不得承诺只用现接口已保证不漏所有新响应窗口。新已出现的消息可提示，但不能擅自换走玩家关注。

## 6. 验收与未完成边界

实施时，当前Chrome自然窗口走“发现→显选→原确认→真实等待/另做事→回应→结果→下一选择→重进”，核可见物件和动作相同、钱/日期/AP/权限/原保存正确。状态图必须能单独判断安排/运行/回应/完成/实收/停止/失败，不能靠开发者旁白补含义。文案检查针对阶段组合，不只断言某个标题出现。

真人理解另验：首幕能否自行指出眼前问题与可点对象，决定前能否复述投入和等待对象，结果后能否自行继续，哪些时刻像填表、哪些取舍想再试。30秒指出第一步、约十分钟首段继续是设计目标，不是本轮测量或保证；正式招募仍0，用户这次反馈不被擅计为正式样本。

本轮仅方案与只读实图，未修复上述原120画面、未实施U4-A、未产生新资产/声音/运行时测试或兼容测试。旧封存、P3正式62/22、原三PNG字节、真人、T17其余、M01暂停、T18与完整goal保持原责任。回滚只撤回独立文档增量，不碰原档、旧证据或规则。
