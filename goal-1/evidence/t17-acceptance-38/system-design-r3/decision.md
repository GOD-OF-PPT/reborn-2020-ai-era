# 主线与系统美术优化方案

2026-10-28。承接用户最新试玩反馈，采用 Game Studio Shared → Game UI Frontend / Game Playtest。当前仍沿已选 A「长日重启」，使用现有 React / TypeScript / Vite；本作以叙事经营和可读文字为核心，继续 DOM、SVG 与原创位图，不迁移引擎。

## 问题判断

主线不清晰，根源是玩家的人生愿望没有持续变成眼前的具体问题。功能能打开、账目准确，只能证明系统接通；如果行动后还要自己在目录找去向，玩家仍像在处理软件任务。默认主线应是“重回2020，用有限的钱和时间，决定自己想过怎样的生活”；五条财富路线、工作与人物生活共同服务这个主题，不能要求每条路线都成功或全部完成。

系统美术的问题也不只在背景。前景物件、阶段文字、操作位置、确认节奏与真实结果没有共同表达同一件事。换一张好看的背景或增加收益卡，无法解决状态难认与行动含义模糊。

## 玩家实际经历

愿望 → 眼前的具体问题 → 比较两种承担 → 显选投入并确认 → 过日子或处理别的事 → 收到真实回应 → 继续、收缩或回生活。

例如，同一位客户提出培训需求：先比较试点与标准范围；答应后看原日期制作，做好后亲手提交；客户真正拒绝，才选择再付成本补救或退款退出；验收后支持与回款分别发生；结果之后可以直接回到生活。不能把“去管理客户”“完成所有任务”当作这段故事的目标。

每幕持续回答四件事：为什么这件事值得我考虑、我现在能做什么、要付出什么、何时能等到谁的回应。当前尝试随真实阶段更新，旧约来源另标；普通消息不抢走关注。年度与季度的叙事问题用于组织理解，不增加强制路线、隐藏奖励或替玩家自动承诺。

## 一屏与交互

固定电影场景，保持一个当前取舍、一个主要可操作物件和至多两个不同旁路。主念头与物件直达同一决定；人物、来信、作品和日期承担叙事。钱与行动保持轻量 HUD，完整依据通过同视口的随身册、章节和页码阅读，页面及面板不滚动。强制责任、现金缺口和保存恢复持续可达。

比较先于表单：先说明各选择的真实承担，再选择资源、日期和金额。取消、翻页与查看原册保留同身份草稿；真正的新承诺重新显选。安排、开工、完成、验收、应收、实收和停止分别表达，不用同一种“完成”样式。存储失败保旧场景，已保存的业务失败则展示真实后果。

等待要有意义。真实客户回应、作品完成与需要取舍的事件应让玩家停下来；不能把每个普通日期变成重复点表。当前公开 nextDate 尚不足以分类全部等待，推广前须完成最小公开意义接口与原屏障映射设计；不读隐藏队列、不跳费用或自动处理责任，也不把现有中性日期表现冒称问题已全部解决。该缺口进入 C-UX09 的体验复核，不能等到最终视听阶段才首次审查。

## 美术、UI与TA

冷青城市、暖灯、木桌、纸白与少量朱红保持统一光向。每条路线有自己的物件语言：作品包、教案与真实名单、服务原约与附联、生态制作册与客户回信、权益凭据；共用状态语言，避免五张同构管理卡。

用展开、收拢、寄出、折联、接触影与遮挡表达状态；暖金强调可决定，纸白承载依据，朱红只标真实未完责任，并配文字和形状。悬停、键盘焦点、选择、确认、等待、保存、只读与候选各有明确表现。动效强调选择和真实因果，减少动效/纯文本保完整操作；不靠持续闪烁、假金币或未发生对白制造热闹。

素材先做状态与动作映射，再补同镜头资产。当前已用内置 imagegen 生成三张透明原创纸件，原字节与提示词分别保存；文字、金额和点击区域保持代码，加载失败回退 SVG。它们与历史三张风格 PNG 的恢复是两件事。五路线统一材质、人物与六年变化、声音成套收口仍按后续任务推进。
