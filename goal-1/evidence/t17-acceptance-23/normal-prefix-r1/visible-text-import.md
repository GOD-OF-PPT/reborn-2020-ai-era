# 可见存档文本导入说明（源码核定，未操作Chrome）

StoragePanel.tsx:8/10/12/16/20：可见textarea的产品state是整份text，检查调用controller.inspectImport(text)，确认调用importNew(text)。独立导入只在入口无current人生且runId尚不存在时提供；同run已经存在不得冒称又导入一份独立人生。rev53用于本轮Chrome起点，rev59供原历史字节核定，不为回退/取代S3已进行的同run进度。保存/候选先沿原产品处理，不用controller全局调用、隐藏IDB或服务暗载。

SaveTextPages.tsx:6/13：240是每页显示/替换的UTF-16字符单位，并非textarea最大长度；textarea没有maxLength。其onChange为 oldText.slice(0,start)+typedValue+oldText.slice(start+240)。因此从入口新开initialText为空的导入对话框、片段1，单次在可见“存档内容”框粘贴/填入完整原raw，产品state可以接到整份字符串；rerender后可见框只显示前240，不能据此断言导入被截断。须用“完整文本共N字”和“检查存档”的日期/revision/背景/runId核实际接收，再明确确认导入。产品codec额外限制UTF-8不超过10MiB，片段数不是许可上限。

不能在已经有原text的第1片段直接填另一整档：原第240字符之后的尾部会保留，形成两档混接。先关闭并从入口重开全空导入。若工具传入整档确有单次限制，合法追加规则是：先填首段；每次用可见片段数/编号跳到最后一段，读取当前最后片段，再把该可见框一次填成“当前末片段完整内容＋下一段”。末片段后的old suffix为空，所以这样才追加；只填下一段会丢掉原末240字以内尾部。不要把“后一段”当空白追加页，也不要反复从片段1填后续块。每次核完整字符数增长；分片不在UTF-16代理对之间断开，不改换行/JSON/校验和。最后先检查，再确认。

旧rev59原文为778801 UTF-8字节、774985字符、3230个240显示片段，末字节为125（右大括号）、没有额外LF；原字节不重格式化或trim。新rev53的实际字节/字符数以本轮真实输出资源说明为准，未预造大小。

此流程使用产品可见文本输入，不依赖扩展file://文件权限，也不请求用户改设置；浏览器是否实际接收和完整导入仍须根在Chrome原窗口核定，本说明不充原生验收。原扩展权限拒绝/超时/Debugger unattached/旧R1原LF审核失败均保旧原件，不用隐藏state或更换seed绕过。
