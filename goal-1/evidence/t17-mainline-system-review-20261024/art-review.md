现有画面已经有统一的冷青城市、暖灯、纸白材质，持续对象、金额/日期/AP与真实保存的区分也明显改善。用户仍需一个可理解的目的、取舍和回响贯穿这些正确步骤。当前跨路线普遍使用“房间背景＋左侧说明＋右侧静物与说明签”，操作大多叫核对、翻阅、等待，人物与物件的变化较少承担叙事。下一轮应重构这段经历的呈现和动作顺序，再成套修艺术；单改间距不能完成这个目标。

## 同一电影舞台的重构目标

场景承担四层：城市/房间给生活背景；人物来往给问题来源；桌面一件主物件承载当前决定；HUD只交代真实资源与保存。主幕一问、一主动作、至多两个不同旁路。愿望只作短目标线，来源季度只在跨季/历史必要时明确一次，完整对象名和原日期仍在近景与原册；不能截断长标题或把责任收进普通信息预算。

物件与桌面建立固定接触关系。先用现有房间与四套kit做分层样张：物件、接触影、必要桌沿遮挡、独立文字/按钮。人物头手保持可读，不让道具看似穿过身体；遮挡层只处理无文字插画像素，不能遮住操作或责任。当前hover整件物件上抬/旋转宜改成局部纸角/轮廓响应，桌面接触点保持稳定。不要只用z-index把冲突叠到别人后面。

选择近景围绕问题组织真实字段，例如“这次为谁做”“谁留出时间”“哪天开工”，一次只展示当前所选产品的真实投入。已选名单、资源、未来日期跨页/取消/原册往返保留；无信息差异的名单可显式批选后逐位核对，不能静默选人、自动签约/收款。完整专业册继续提供所有原能力，作为深层资料与复杂处置入口。

确认第一眼应能复述：具体对象和主体、现在实付还是预留、共享AP/资源、开工与预计反馈、后续支持/退款/权限。完整条款留原分页，固定footer继续用原preview/confirm。保[App原提交链](../../../src/ui/App.tsx)（第300行），不新增一个假“交付”按钮只负责开表单，也不增加重复确认关卡。

## 完整视觉状态语言

| 状态 | 场景/纸签与玩家动作 | 因果约束 |
|---|---|---|
| 可决定/聚焦 | 暖金细轮廓＋真实动作名；鼠标、键盘指向同对象。 | 不是单凭亮色猜能否点，资格不足有具体原因与可行去向。 |
| 草稿/已选 | 未落章的纸角＋已选对象/名单；“待确认”。 | 选项预看不切已选对象，不执行命令，不改日期。 |
| 原确认/保存中 | 承诺纸面突出主体、钱、AP、日期；保存中保旧物件。 | 确认不是已保存；不先加完成痕迹或播放收益。 |
| 已安排 | 虚线日程条、“已预留，尚未开工”。 | 资金和AP预留不冒实付；原开工日仍须实际到达。 |
| 进行中 | 实线日程＋当前原任务/下一反馈；已开工费用明确。 | 不造实时百分比、不用现实秒数自动推进。 |
| 等反馈 | 回信留位/日期票根＋等谁、为何等、何日；可去做别事。 | 原AdvanceTime、费用、事件/交付屏障继续；0AP仍有原有限出口。 |
| 实际完成 | 本对象完成页/交付印记，原结果可展开。 | 完成与亲手提交、验收、收入、现金仍按各路线真实规则分别表达。 |
| 实际到账 | 独立收据列实际日期/金额，预款、余款、费用分列。 | 不用总余额变化作本单净额；同次原子回执只拆阅读，不虚拆命令/可停留应收状态。 |
| 停止/非成功 | 划线但保留的原页；未完支持/债务用朱红折签。 | 原成本、余额/保护、应收应付仍在，不暗示退出清债或免费重开。 |
| 到期/强制责任 | 朱红角签＋具体原因、期限、原处理动作；原书签留位。 | 不被1主2旁预算删除；处理后回同一对象，不自动换新单。 |
| 未保存/冲突/只读 | 未签章/锁形＋具体状态；原候选、导出、恢复方向可达。 | 全幕集中说明一次原因，受限按钮关联该原因，减少重复报警；保旧提交，不以淡出隐藏失败。 |

动效先限定三类：聚焦局部响应；显选/原确认的纸签变化；真实saved后的一次结果印记/日期变化。没有新事实时不播收益或升级。减少动效直接呈现最终文字/形状，纯文本保同对象、同动作和全部原记录。所有HUD/纸页按钮成对定义默认、hover、focus-visible、受限配色；R4原账入口浅底浅字说明全局button皮肤和局部状态需一起核，不能只核静态默认色。其局部CSS修已写，修后Chrome证据仍按原任务另核。

## 优先交一段完整经历

先以真实首单检验共同语言：Jan1来信说明¥1,300报价、最迟Jan5答复、¥500/1点于Jan5开工承担；点物件直接核这份承诺。保存后先是已安排；Jan5实际开工才换进行中，Jan19作品做完仍待亲手提交。Jan20按原回执展示复核与实际到账；若原规则同次提交完成两者，仅按阅读顺序呈现。之后提出“再试这份手艺，还是先安顿本季工作生活？”对应真实可达选项，不保证当季再接原首单。投资/自由开局仍各自先给明确对象与结果，不能被这段教学替代。

这段同时交付主幕、选择、确认、等待、失败保存、真实结果、原册返回与美术状态，不能先做一张漂亮首图。再把同样结构用于视频的制作/亲提/修改/实收、课程的准备/保护/教学/支持退款、中转的服务/实计/更正/收取、生态合同与明确架空权益。真实生活改善仍只在原任务完成后改房间，不随收入任意豪华升级。

## 明确验收与防止再次碎片化

1. **目的和行动**：试读首幕后能指出眼前对象、真实动作、代价和反馈日；结果后能说出下一种可行选择。30秒首幕识别沿36号文作为待验设计目标，真人当前仍0，自动化不能替代这一项。
2. **真实因果**：同一实际ID贯穿选择/确认/原册/日历/保存/回响；预留→开工→完成→提交/复核→实收按原规则，强制责任优先，普通消息不抢关注。每条素材状态都能追到公开来源。
3. **一屏完整性**：只用当前自然窗口实核每一主/旁动作、固定footer、原分页、长名单/长标签与完整责任；不滚动、不裁切、不缩字，不开移动/多尺寸/缩放/几何专项。可见页与AX全分页分别记。
4. **可操作状态**：默认/hover/键盘focus/受限均可读且形状与文字一致；减少动效不改语义，纯文本/图片未载入仍可完成原路径。点击正确对象、失败保存后旧物件不变均须真实动作验证，不能由截图推断。
5. **产品收益证据**：在有意义取舍与结果之间记录玩家困惑点/重复操作，不以测试总数、完成更多路线、更多背景图或自主脚本当作趣味性通过。小轮无提示玩家试读若尚未安排，该门槛继续保留；不把“暂未测试”写成已经满意。

本轮只有此只读建议。优先让一段真实经历在目的、行动、艺术和结果上同时成立，再复用到原全部内容；不改框架，不启动兼容性工作，不通过削掉真实规则/旧责任换取简短画面。
