## 公开接口与独占责任

| 模块/接口 | 调用者得到什么 | 必须遵守的合同 |
|---|---|---|
| money、calendar | 有界整数/万分比、累计费用、ISO日历和季度 | 金额以分保存，临时BigInt不进入状态；不读系统今天或本地时区 |
| createLedger / applyLedger | 分主体现金流水、财务余额、占款和回执 | operation.id是稳定的经济发生项ID；同ID同意图不重复生效，不同意图拒绝；失败不改变输入 |
| accountFunds / accountPosition / metricsFor | 当前主体资金、资产负债与期间/业务口径收入成本 | 可用现金不等于利润；保护缺口/应付不隐藏；企业现金不再加到个人持股财富中 |
| createEconomy / applyEconomy / actionBudget | 共享四点预算与资金联动的行动生命周期 | 草稿不扣资源；预留资金和注意力；执行扣点扣费；中断不退已发生资源；完成不再扣一次 |
| assertLedger / assertEconomy | 已知类型状态的跨记录不变量 | 检查配平、非负玩家现金、保护、收入/应收、行动与资金关系；不是未知JSON的完整导入解码器 |
| queueEvent / advanceTimeline | 带阶段/优先级/稳定ID的日期队列和发生回执 | reduce必须是纯函数；后续事件加入当前推进；不能回到过去；必要处置暂停；单次10000事件上限防止无限续发 |
| advanceEconomicTime / acknowledgePause | 经济发生项与时钟一致地推进、处理资金缺口 | 操作日期等于事件日期；缺口在未来现金到达前暂停；恢复队列不删除欠款，不代表完成调查或恢复控制 |

规则代码位于src/core，仅依赖同目录模块和ECMAScript标准能力；tsconfig.core.json使用ES2023且不包含DOM或Node类型，作为独立编译检查。测试/证据采集与浏览器入口在外层，不将React、文件系统、网络或真实时钟引入规则。

## 账本与财务维度

个人与企业分别有现金账户；external是虚拟清算对手，允许有界的带符号清算余额，不是玩家可支配现金。每笔现金交易在账户之间配平，附日期、businessId、contractId、sourceEventId和referenceId；非现金收入/成本更正也保留来源和原项引用。

RevenueBalance只记录合同财务维度，不能代替T06的生产/验收合同；SupplierPrepayment不授予供应资格；InvestmentPosition不授予治理权。接入业务时由各业务命令先验证前提，再调用共享账本，UI不能直接调用原始财务发生项创造收入或估值。

已支持：期初资金、已确定收入、即时/到期费用、计划/订单/冻结占款、计划转订单、客户预付保护、交付释放、交付前后退款、应收形成/收款、供应预付/实际消耗、个人注资、现金换资产、非现金估值与累计费用。退款缺现金时转为应付并保留应退保护；部分支付后仍显示未结清。交付后退款冲减收入，不制造未交付负债；额外赔偿须另记成本。

即时费用与charge_fee要求有实际可花资金；已到期、应计且可能缺钱的费用走due_expense并保留应付。后续业务适配器须正确选择发生项，并维护收费义务/账单版本，不能把未支付费用丢掉。费用按feeId累计计费基数，拆成多笔不会重复四舍五入；同feeId不允许悄悄改变主体或费率。

预款不能支付别的业务、投资或分红。普通新支出、投资和资金计划在有逾期应付时受阻；明确分类的recovery支出/行动仍需现有资金、同一行动预算和合法资金来源，不提供免费应急回合。恢复分类必须来自后续已验证命令/模板，不是让UI任意改标记绕过限制，也不授予任何AI权限。

个人财富由其自身现金、应收/预付资产、持有投资价值减债务构成；同一企业的现金不在个人持股价值之外再次相加。当前value_asset只记录已提供的估值，不产生现金或已实现收益；真实撮合、部分成交、卖出成本分摊、融资/借款、分红、持股比例/治理/锁定仍由后续T06/T08/T13补齐业务入口与相应共享账本操作。

## 行动与日期

draft → reserved → executed → completed/interrupted；仅draft/reserved可取消或重排。每季4点按startAt所在季度计量，所有主体共用同一份个人注意力。跨季完成不再消耗新季度点数；它占用的真实团队/制作容量由T06按完整日期区间验证。

执行必须发生在排定开始日；提前或错过日期不能悄悄缩短工期，需在未执行时重排。执行成功才转换资金占用并记成本；资金冻结等条件变化导致失败时，不扣点、不留下半条结果。行动仍reserved时，原始资金释放/消费不能绕过行动流程，使行动变成无资金但占点的悬空记录。

同日顺序：世界更新→确定到账→到期义务→玩家动作→撮合→快照；同阶段按priority、instanceId稳定排序。读取/展开不处理队列。事件入队保存数据快照，外部对象之后变化不重写已入队内容；相同实例重放不重新生效，更换载荷而复用ID明确失败。

队列会在付款缺口或处置请求暂停；确认延期推进后，原欠款仍在并继续限制普通扩张。已经结清的历史欠款回执不会误触发新的缺口暂停。循环续发超过单次上限会整体拒绝，不提交半程候选，不能把限额当作免费推进或删除事件。
