# 08｜技术实施方案 v0.2

状态：待实现。当前仓库没有前端工程、可运行游戏或真实行情服务；下列模块和测试是交付目标，不是已经存在的功能。

## 1. 架构与边界

工作选型：React + TypeScript + Vite，分层二维场景与普通网页组件。先单人本地运行，不做账号、真实支付、券商接入或在线模型依赖。Vite官方提供相应工程模板；实际开工再核验版本并提交锁文件，避免把“最新版”写死在旧文档。参考：[Vite官方指南](https://vite.dev/guide/)。

架构分四层：规则核心处理命令和事务；内容提供有限条件/效果与文本；UI只提交意图、展示投影；持久化保存版本化状态和日志。禁止UI直接加钱、内容eval或运行时模型裁决收益。

## 2. 拟建模块与接口

| 模块 | 职责 | 主要输入/输出 |
|---|---|---|
| core/time | 季度规划、月度费用、日期事件顺序 | advanceTo检查点；到期事件/付款 |
| core/actions | 预留、执行、取消、维护与中断 | 指令；预算账本/不可执行原因 |
| core/ledger | 分账户现金、预付款、应收应付和交易 | 成对流水；现金/利润/义务投影 |
| core/opportunities | 五类机会公共生命周期、市场阶段与容量 | 机会配置、业务实例、经营结果 |
| core/market | A股订单、持仓、交易检查点与公司行动 | 版本行情；成交/未成交解释 |
| core/business | 内容、课程、中转的专用产出与结算适配 | 流量、学员、用量；收入/退款/负债 |
| core/equity | 非上市项目资格、谈判、稀释与退出 | 权益协议；股权/治理/锁定状态 |
| core/world | 史实、虚构、架空、记忆分域和外部组织 | 时间锚点；跨路线影响与因果 |
| core/crisis | 线索、证据、控制、恢复和残余问题 | 部署状态；受控范围与恢复成本 |
| persistence | 快照、版本、导入、迁移和写入冲突 | 存档封套；成功或保留旧档的错误 |

所有路径拟位于src下，尚未创建。测试目录随后对应这些边界；不要用五份独立游戏状态复制五条赚钱路线。

## 3. 统一状态与命令契约

GameState至少保存：rulesVersion、contentVersion、saveVersion、schemaVersion、worldSeed、各随机域状态、当前日期/季度/阶段、revision、背景、行动账本、各账户、订单/持仓、业务实例、权益协议、人物承诺、权限与依赖、世界领域、记忆、危机、待发生后果、已处理命令和因果记录。

命令封套：commandId、expectedRevision、actorId、kind、payload。执行流程：校验格式/版本 → 校验当前前提/预算/日期 → 在副本计算全部效果 → 检查不变量 → 原子写入状态、流水、因果与命令回执 → 持久化 → UI反馈。

相同commandId返回已有结果；旧revision拒绝并刷新，不静默合并。不能先扣钱后发现选项不合法。预览与执行使用同一套规则，但预览不得改变随机状态、隐藏事实或账户。

事件ID不等于实例ID；同一课程多期可以生成多个实例，每一期回款与退款只结算一次。日期同值使用稳定排序；工资和义务不能按UI渲染顺序结算。

## 4. 五类机会的专有状态

A股：assetId、venueRulesVersion、priceDataVersion、数量/成本、订单提交与可成交时间、冻结额、公司行动。真实标的与模拟标的不能混用未注明价格。

短视频：作品批次、制作状态、返工、素材权益、受众、有效流量、可变现资格、商单、平台应收。课程：课程版本、案例、课期、学员、交付/退款、支持容量、预付款负债。中转：供应与故障域、价格生效区间、客户余额、供应预付、已消耗用量、上游账单、赔付、维护容量。

项目投资：主体、关系类型、融资意愿、介绍资格、尽调状态、估值条款、老股/增资类型、股份、治理/退出权限；架空DeepSeek谈判始终携带counterfactual标签。

数据字典与事件例子见[内容契约](15-content-contracts.md)。

## 5. 确定性、会计和隔离

金额以安全范围内的整数分保存；乘除、费率与四舍五入策略集中实现并测试溢出。流水记录transactionId、账户、币种、科目、发生日期、来源实例和原因。客户余额不得当现金利润；转账不能创造净资产。

随机算法及版本要锁定；市场、机会事实和危机使用独立的稳定随机域，避免新增一条闲聊改变全部行情。隐藏事实生成后写入存档；读档与调查不得重抽。

历史行情和模拟行情有独立数据模式。真实数据需要来源、使用条件、日期覆盖、上市/退市/停牌、公司行动、复权及交易制度口径。资料未通过校验时使用明确的模拟模式，不在运行时抓取未经核验数据补洞。

## 6. 存档与失效处理

IndexedDB作为候选本地存储，配手动导出/导入、最近有效快照、内容哈希与版本迁移。浏览器存储可能被清理或回收，不能承诺永久保存；依据：[MDN存储说明](https://developer.mozilla.org/en-US/docs/Web/API/Storage_API/Storage_quotas_and_eviction_criteria)。

导入验证大小上限、JSON结构、数字边界、日期、引用ID与版本。未知高版本只读提示或拒绝，失败保留旧档；迁移先备份。多标签页写入按revision检查；写失败明确显示未保存并允许导出，不能只更新UI成功提示。

存档中的文本一律转义，内容操作符使用白名单，禁止任意代码和外链执行。单人游戏不承诺防手改作弊，也不为此扩大隐私采集。

## 7. 实施顺序

先建空工程与规则测试入口；再做现金/行动/日期/存档；接入机会公共状态机；分别用股票、课程、中转证明不同经济模型；补视频与项目投资；接历史跨路线冲击与局部危机；最后连接半写实工作台与24季度内容。

阶段提交应能单独验证，不先开发真实API聚合服务、在线视频生成、交易账户或融资平台。生成模型可辅助制作开发素材，但发布运行不需要它决定胜负。

规则测试覆盖[验收矩阵](14-acceptance-matrix.md)，从确定性固定例子到事件链回放，再到UI路径。候选工具在工程任务中选型并锁定；当前不能执行不存在的npm脚本。

发布前核验全流程存档、24季度可达性、五类路线与非创业结局、资产和历史来源、关键操作键盘可达和目标视口。CI、部署平台、公开站点、许可和收费另行决定；本次不添加密钥、部署配置或实际远端Issues。
