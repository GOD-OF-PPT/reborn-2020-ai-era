# 08｜技术实施草案

状态：方案，不含已建工程或已通过的游戏测试。库版本、部署服务与最终依赖应在开工时按官方文档核验并锁定；不要假设本资料仓库已经可以运行npm命令。

## 技术取向

建议React + TypeScript + Vite制作电脑优先的单人网页版本。以分层二维资产和网页动画实现房间，主要操作使用普通网页组件，不先引入三维引擎。首版不需要账号、收费后台或在线模型服务。

拟定三层：规则核心、内容数据、表现界面。UI发出指令，核心验证并产生状态与事件；内容提供条件和文本，不允许任意脚本执行；表现读取已确定结果，不能自行加钱、推进时间或修改风险事实。

## 拟定工程目录（尚未创建）

`src/core`：时间、财务、行动、项目、人物、世界、危机与确定性随机。

`src/content`：历史锚点、普通事件、架空分支、人物文本与配置。

`src/ui`：房间、工作台、事件、记忆、危机、结算与菜单。

`src/persistence`：存档版本、迁移、导入/导出与本地持久化。

`tests`：规则不变量、固定种子回放、事件覆盖和端到端场景。

这些路径是架构提案，不要在交付说明里称为已有模块。

## 核心数据

GameState：规则版本、内容版本、存档格式版本、世界种子与随机状态、季度/阶段、玩家背景、个人财务、公司财务、行动账本、项目、人物、记忆、世界域、危机、已执行事件、待执行后果与因果日志。

事件配置：唯一ID、类型、来源、有效窗口、前置条件、优先级、互斥组、隐藏事实初始化、可见线索、选项、成本、效果、延迟事件和显示文本。

不得用eval运行内容条件。使用有限、可验证的条件和效果操作符；内容导入也不应允许任意外部代码。

## 结算流程与确定性

先校验版本和指令 → 校验资金/行动与资格 → 建立一次性事务 → 计算行动/风险/世界状态 → 写入账本和因果日志 → 提交事务 → 保存。

相同存档、规则与内容版本、随机状态及动作序列得到相同结果。随机值由核心统一管理，不由UI渲染次数产生。读档不重抽已确定的商业真相或历史事件。

历史锚点按时间顺序发生；季度内的重大事件有阶段标记，避免在2022年第四季度开始时就将11月末能力当作全季度可用。

现金按整数最小单位保存，转账成对。事务有唯一ID，重复点击、重复消息与读档不重复结算。

## 存档

拟用IndexedDB保存本地存档，并提供导出/导入、最近有效快照和损坏校验。浏览器本地数据可能因用户清理或存储策略丢失，不承诺永久可靠。正式选型依据需在实现时查阅浏览器官方文档。

导入检查文件大小、格式版本、必要字段、数值边界与未知操作，失败时保留旧存档。迁移建立备份，不静默重置。存档未来含用户输入时，渲染必须转义，不能将其当HTML执行。

## 生成式AI的边界

开发期间可辅助草拟文本；运行时不是必需。后续即使生成新闻或对话，也只能表达规则已确定的结果，不能裁决收益、胜负或历史条件。不得在客户端嵌入API密钥。首版不会将玩家真实身份或账户数据发送到模型。

## 测试顺序

先做季度、资金、行动预算与重复结算测试；再做历史因果、世界独立推进和记忆域失效；再做危机中断、人工接管与外部冲击；最后做完整路线和界面回归。

重点覆盖相同记录回放、季度跨月现金低点、个人与公司隔离、隐藏事实不重抽、危机后恢复、读档和双击、未满足条件的禁用选项解释。

性能、浏览器范围与截图基线在样板中测量再设门槛。当前不编造帧率、完成时间或测试覆盖率。

## 安全与发布

资料阶段不启用GitHub Pages，不创建部署密钥或CI秘密，不付费开通云资源。开源许可与公开上线需单独确定。已有图仅概念使用，发布前核验品牌、角色、字体与素材条件。
