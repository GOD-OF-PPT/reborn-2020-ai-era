# 32｜界面、流程与视觉重构 v1

依据2026-10-17[用户补充原话](../goal-1/ui-redesign/input.md)。这是D01设计交付及D02实施合同；D02将其接入真实React前台，业务规则仍沿T13合同；本轮验证和剩余范围记录在goal执行证据。设计图、可交互样稿、已接入运行时与真人体验是不同证据。

## 1. 现状判断与设计目标

审计基线db14cb040a626fed34cd2c35a20f14b4f9631b57。已有规则和保存底座应保留，但前台没有形成游戏的表达。

| 现状 | 玩家负担 | 重构决定 |
|---|---|---|
| App十个同级菜单，经营五线、例行与总览并列 | 开始前就要理解模块名 | 四个主入口；经营内五线、季度内例行，原功能全量映射 |
| QuarterPanel把财务、引导、首单、旧业务等连续堆叠 | 下一步决策被长文与按钮淹没 | 季度阶段、一个主决策、独立全部义务队列、按需经营入口 |
| 大量深色面板、同形按钮与说明 | 缺少空间、节奏和重点 | 房间/章节氛围＋高可读纸面操作层，主次动作和排版层级 |
| Home一次展示背景/愿望/引导和完整说明 | 像创建记录，缺少重来一次的感受 | 房间→背景/愿望→模糊记忆→可跳过建议；不替玩家执行付费安排 |
| 操作反馈主要是状态文字与新数值 | 不知道发生了什么、为何发生 | 已提交结果卡：原值/变化/现值、回款/成本/净额、剩余承诺与来源 |
| 五路线虽有规则差异，但表单都很长 | 看起来都在填配置 | 每线独立决策摘要、状态推进与专业详情；保留全部合法操作 |

目标是让玩家先理解“我在怎样生活、现在该决定什么”，再按需要深入账目。不能用装饰、自动赚钱或删掉复杂义务达成简洁。

## 2. 视觉语言与场景

沿用半写实电影感：普通2020出租屋、冷色窗外/暖色台灯、真实木材与纸面。避免科幻HUD、全息屏、未来机器人和默认豪华办公室；不固定玩家性别或真实人物脸。

新生成[房间场景](../assets/ui-redesign/room-2020-v1.png)用于开局与章节横幅；[工作台概念图](../design/ui-redesign-v1/workbench-concept-v1.png)只指导气质和层次，不能直接当网页截图贴满产品。生成图没有严格保留四项导航，HTML样稿已明确绘制导航；概念图局部文字、图标和布局不构成运行时合同。

图片不承担金额、按钮、长文、图表和状态。主操作区是平面HTML，不能塞进透视电脑屏幕。原三张PNG仍缺失；本轮图片是新生成资产，不能写进原概念图路径冒充原始字节。来源、提示词、尺寸与SHA256见[资产清单](../design/ui-redesign-v1/assets-manifest.json)及[完整提示词](../design/ui-redesign-v1/generation-prompts.json)。内置image_gen生成，未调用CLI或需要API key的路径。

| 用途 | 设计值 |
|---|---|
| 基底/操作纸面 | #f5f0e7 / #fffcf6 |
| 正文/次级文字 | #292b27 / #68645c |
| 主动作/已确认金额强调 | #805722；白字，显著区别于普通描边按钮 |
| 记忆/时间线 | #48657c；不依赖颜色表达真伪/期限 |
| 错误/义务 | #963e31，配标题、说明和可执行处置 |
| 字体 | 系统中文衬线标题、系统无衬线正文、等宽数字；不分发未核验字体 |
| 间距/结构 | 8px基础、24/32px组距，少量直线分隔；避免所有内容变成同等圆角卡片 |

## 3. 信息架构

主导航：**本季 / 经营 / 记忆 / 账本**。品牌返回房间仍须检查未保存候选。正式入口只有新人生、继续、存档与设置；样稿为了评审常显四项页面导航，不意味着未开局即可经营。

- 本季：简报、计划、关键抉择、结果、下季草稿、所有义务/异常、例行入口。
- 经营：五路线持续可发现；每线内列当前业务、准备/资格、下一步、已发生结果、专业操作。
- 记忆：模糊记忆/本局观察/失效前提分开，历史来源、已知因果、收藏；后续危机证据链从此可回看。
- 账本：默认四个问题、主体切换、详细账目/资产/合同/存档/备份。市场下单仍有独立账户选择，不能由全局配色猜执行主体。

日期、当前主体、可花、行动/预留、保存状态始终有可靠可读入口。公司资金不能并入个人余额。普通重点1主2支只约束强调，全部义务与独立风险不得折叠到不可发现。

## 4. 完整玩家流程与状态

| 阶段 | 第一层 | 深一层 | 必须保留的约束 |
|---|---|---|---|
| 新人生 | 房间、2020、继续/重来 | 两背景、愿望、可选固定种子/自由安排 | 背景参数真实；不默认执行推荐组合 |
| 简报 | 一段年代/生活氛围、现在可花、本季重点 | 全部到期项、现有业务摘要、记忆来源 | 新闻不推进世界；不泄露精确隐藏结果 |
| 计划 | 工作/机会/维护的少量方案 | 日期、资金、行动、团队、保护款、最低现金 | 选择草稿不等于授权；同序手动与例行一致 |
| 确认 | 主体、实际成本/本金、行动、日期、当下收入 | 退款/支持/融资/锁定/退出条款 | 预览只读；新融资/交易/招生/扩权独立同意 |
| 执行 | 开始/进行中/已完成/待验收/待回款 | 实际任务、提交/复核/收款回执、期限默认 | 不自动跳过需要玩家确认的命令；不靠动画推进时间 |
| 结果 | 回款、成本、净额、尚欠什么 | 工资/投资/副业分口径，来源与未知因果 | 仅已保存结果；浮盈和预款不算经营利润 |
| 下一季 | 结果摘要、旧义务、可复用草稿 | 条件变化与授权范围核对 | 不自动接新融资/招生/交易/代理权限 |
| 年度/尾声 | 愿望与已兑现生活、已确认因果 | 财富/义务/控制权/关系、可选分享 | T15/T16接入真实数据；不清债、不峰值变现、不泄密 |

季度阶段是信息组织，不是新的规则时钟，也不强制每季按按钮走四遍。已有任务可在对应状态直接继续；离开/返回页面不消耗行动，不新增随机。

| 视频 | 受众→作品→客户/平台→回款 | 素材/年代资格、制作/人工校正、范围修改/谈判、播放/咨询/合格收入、cohort |
| 课程 | 学习目标/案例→班期→教学→支持 | 权利/样课、班额/资金、预款保护、阶段退款/补支持、七天更新/停售、进阶新需求 |
| 中转 | 供应与服务周期→用量→账单 | 许可/技术适配、预付/信用、成本授权、审计/更正、供应贷项、故障域、停站旧余额 |

## 6. 财务、事件与失败态

默认财务回答：现在可花、本季已实现净额（主体与口径明确）、还欠客户/他人什么、最早确定现金缺口。随后展开预款、应收应付、冻结、供应预付、证券市值、私股成本/估值/锁定。大额/停业/融资确认主动展开相关义务与赔偿，不能只给一个“确定”按钮。

事件用一个连续阅读的抉择区；普通信息合并标题但保留所有实例。危机用持续处置页呈现权限、自报、独立验证和恢复代价，T14接真实能力，不靠红色闪烁或现实倒计时制造压力。

保存中保留已核对预览，按钮防重复；真正提交后才触发结果反馈。失败时主区保持旧完整提交，候选单独标“未保存”，保留导出/原候选重试；只读/冲突/不支持写锁有独立说明和恢复路径。零现金/行动仍可有限停止、延期与推进，未付债务持续可见。

## 7. 效果与无障碍

150—240ms淡入/面板位移用于建立层级；结果动画只能在已提交数据上播放，关闭动画不改变最终状态。章节过渡可跳过，不强制等待、不在背景循环抽随机。首版不自动播放音乐，不引入第三方SDK。

1366×768、1280×720首屏可见主决定与关键资金/义务提示；1920×1080保持最大阅读宽度。窄屏单栏，不能简单缩小桌面。真实200%缩放、键盘/焦点返回/对话框、文本模式、prefers-reduced-motion、错误非仅颜色在D02/T15验收。等效窄视口不冒充真实200%。

## T15-N增量：人物与日历上的牵挂
