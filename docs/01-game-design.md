# 01｜核心玩法设计

状态：待原型验证。本文描述拟实现规则，不代表已有功能。

## 季度循环

读取存档与期初状态 → 推进该时点已到期的世界事件 → 浏览新闻、消息和记忆 → 安排行动与资金 → 逐项执行并处理事件 → 财务与世界结算 → 查看因果记录 → 保存并进入下一季度。

普通行动按季度计。重大事件使用季度内部的明确阶段或日期顺序；新闻不能提前给尚未发生事件的能力加成。危机可以中断未执行行动，但不重置预算、不退还已发生的成本。

玩家可以随时阅读，不消耗行动。真正消耗的是学习、调查、经营、谈判、合作与休整。每次确认前可看到明确成本、条件、承诺及已知的不确定性。

## 主路线

### 职业与投资

工作形成现金流和能力积累；调仓体现机会判断和流动性取舍；后期通过项目融资、合作和真实治理权参与技术发展。被动买入公开交易资产主要改变财富，不直接替公司提供新研发资金，也不自动授予战略控制权。

这条路线有完整结局，不作为创业的低配版本。可以通过职业岗位或资助项目影响历史，也可以赚够钱后保持普通生活。

### 应用创业

识别需求 → 制作原型 → 寻找试点 → 获得回款 → 选择扩张、融资、转型或出售。新模型发布既可能降低开发门槛，也可能削弱现有产品的差异。早期积累的客户、流程与信任决定后续选项，不只是增加抽签成功率。

### 路线切换

允许先就业后创业、卖公司回归投资、研究项目转向服务。不清空历史，原有承诺、生活状态与合作后果继续存在。公司资金和个人储备不随切换混为一谈。

研究、开源工具、部署生态先作为两条路线共享的项目，后续再扩充。

## 人物系统

长期人物至少记录目标、信任、共同经历、尚未兑现的承诺与当前处境。不能用一个通用“好感度”替代全部关系。

- 林舟：虚构技术伙伴，希望做有原创性、可持续的工具；不必接受无限定制工作。
- 早期客户：曾在产品粗糙时提供试点；看重承诺与实际收益。
- 关键员工：提供独立观察，也有职业与生活需求；不是永不离开的功能按钮。
- 生活关系人物：关注主角生活是否仍由自己决定；身份与姓名待内容设计。

人物会按自己的目标行动。没有玩家支持，团队可能被收购或解散；缺少参与资格时，玩家无权替别人作最终决定。

## 事件结构

“准备—抉择—后果—回响”。每个重要事件包含当前上下文、触发条件、已知信息、选项、即时成本、延迟影响与因果入口。

失败可以导致缩减业务、重新就业、出售资产或接受接管。不要以无预警的随机死亡、随机破产结束多数经营分支。真正严重且不可逆的结局应有相应因果链和明确的架空标识。

## 结局与重复游玩

分别汇总个人现金与资产、事业持续性、控制权、关系与承诺、生活状态、技术贡献、世界控制情况和历史偏离。不存在唯一的财富最高分通关。

重复游玩依赖不同背景、路线、合作与机会条件。随机性改变虚构机会和风险，但不随意洗牌所有真实历史。不同结局允许双赢，也允许可解释的代价；禁止每次成功都强制反噬。
