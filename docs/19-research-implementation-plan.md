# 19｜竞品优化的实施补充与验证计划 v0.4

本页将[调研](17-competitive-research.md)转为[玩家流程](18-revised-player-flow.md)的实现合同。**没有实现游戏、没有实际试玩结果、没有创建远端任务或部署。** 原P001—P022、Q01—Q40、S01—S05保持编号和未完成状态；本轮新增D401—D410设计决策、X01—X14补充验收、UX01教学规格。不得把X用例注册说成测试已通过。

## 1. 文档权威与升级边界

经济02仍决定钱、日期、行动、退款、停业和终局义务；内容15仍决定条件/效果与幂等；技术08仍决定规则、持久化与安全。v0.4核心01、界面06和流程18替代旧页面顺序与信息展示；本页补充应用层接口和验收，不另建五套引擎。

[backlog](../planning/backlog.json)保持v0.3的22项基础功能任务；[competitive-design](../planning/competitive-design.json)是v0.4增量映射，关联基础任务而不伪造新Issue。基础任务未完成则不得宣称依附它的增量完成。完整首版完成条件为原Q集合及新增X集合均有证据，而不是只跑新的体验检查。

## 2. 拟新增接口，均待实现

| 接口/实体 | 输入与输出 | 不变量 |
|---|---|---|
| QuarterBriefProjection | 当前可见状态→最紧迫义务、相关机会、日期与主体现金 | 只读，不抽随机；折叠不删除原事件；不混合个人/公司 |
| OpportunityDecisionView | 业务实例/可见知识→选择、成本、资格原因和承诺 | 2—3项默认方案不是能力限制；详情保留完整选项；无隐藏事实泄露 |
| RoutinePlan | runId、accountId、业务范围、白名单动作、预算/容量上限、有效期、暂停条件 | 下季复用生成草稿；明确确认后才执行；不自动开新业务或扩权 |
| ExceptionQueue | 到期事件实例→按日期/严重程度/稳定ID排序的处置项 | 1主2支只限制普通展示；强制事项不受截断；默认结果不自动接受付费 |
| ReceiptProjection | 已提交交易/交付事实→回款、成本、利润、限制资金和因果 | 工资/预款/浮盈不冒充副业利润；凭证不能再触发一次收款 |
| PreparationLink | 记忆ID、已知条件、准备动作和案例→节点发生时的选项变化 | 收藏免费，实施仍消耗预算；真实能力不能提前可用 |
| YearReviewProjection | 年度已提交事实→愿望进展、生活选择、世界变化 | 不推进日期、不免费消费、不创造股票收益、不泄露未选真相 |

推荐放在现有拟定架构的应用/投影层及各路线适配器；不要为了这些接口先搭建真实交易、内容生成或中转后台。正式命令继续经技术08校验runId、载荷、revision和幂等ID，再原子提交与保存；保存失败不能显示成功凭证。

例行方案的批量执行与逐项手动执行必须在同一版本、随机状态和日期顺序下产生相同规则状态。界面是否展开或播放动画不改变结果。规则侧计算每个实际到期动作，UI可以聚合展示，不能用平均利润代替真实流水。

## 6. 试玩设计：先验证理解，再比较节奏

建议首轮8—12名目标玩家，覆盖策略经验高低及AI知识高低；这是招募目标，当前样本为0。用相同状态/可选动作制作v0.3多页灰盒与v0.4聚合灰盒，交叉安排先后顺序，降低学习顺序影响；不同时更改数值奖励，以免把多给钱误当更好操作。

任务包括完成第一单或自主投资、解释可花现金、选课程班额、处理一次上游变化、指出一次历史改写。记录开始/结束点、真实用时、页面切换、无决策确认数、错误借用预款次数、求助、主动展开总账以及未完成原因。主任务分支不同应分组，不拿投资持有者未兑现作为教学失败。

待验证目标而非成绩：选择接单的玩家在首个教学季度获得可解释回款；教学主动用时目标不超过10分钟；普通季度目标3—6分钟；完整24季度主动游玩目标90—150分钟，允许分次继续。长阅读、无障碍需求和自由探索单列，不自动标为失败。至少80%的测试者应能在不打开总账时解释可花现金和下一项承诺；小样本报告实际人数/总数，不声称统计显著或预测商业留存。

操作减少但理解恶化则不通过；同种子同动作收益改变则先查规则错误。玩家感到被迫追热点时降低信息压力，不提高收益倍率“修复”；各路线手感相同则重做关键选择，不增加更多统计指标。

记录默认在本机，试玩者同意后手动导出匿名记录；不默认接分析SDK、不收真实财务/账号。发布与收费、后台监控、部署均另行决定。
